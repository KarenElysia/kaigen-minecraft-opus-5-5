# 技術アーキテクチャ

## 構成

- 言語とエンジン: C、HZ（Kaigen）エンジン。libc を使わず、エンジンの標準ライブラリを使う（AGENTS.md）。
- 対象: Windows（Direct3D 12）、ブラウザ（WebAssembly + WebGPU）。モバイルブラウザは常に単一スレッドのビルドで動く。
- コード: `src/webcraft/`（約9,900行）、シェーダー: `shaders/`（34本、単一ソースを各バックエンド向けにコンパイル）。
- アセット: なし。テクスチャ・アイコン・音は起動時に手続き生成する。
- 設定: `hzproject.hzt`（`src_roots src`、`shader_roots shaders`、`test_roots tests`）。

## スレッドモデル

エンジンはアプリを全コアでロックステップ実行する。`app_init` と `app_update_and_render` は全レーンで走り、
`lane_sync()` で同期、単一スレッドの処理は `is_main_thread()` で分ける（`wc_game.c`）。

ワールド生成・ライティング・メッシュ化は `WcJob`（`WC_JOB_GEN` / `WC_JOB_LIGHT` / `WC_JOB_MESH`）として共有リストに積まれ、
全スレッドが時間予算付きのラウンドで取り合う（`wc_world.c`）。3×3 の窓が重なるジョブは同じフレームで実行しない。
ジョブ時間の推定値は実測で指数移動平均される。

## ワールドデータ

- チャンク格子は 64×64（`WC_GRID`）のリングで、描画距離は最大 24 チャンク。
- ワールド用アリーナはレーン数から実際の上限を計算して確保する（iOS は 2GB を予約できないため）。
- プレイヤーの編集はチャンク単位のハッシュ表 `WcEditStore` に記録し、再生成時に適用する（`wc_storage.c`）。

## 描画パス（`wc_render.c` の順）

1. GPU カリング（チャンクの quad をカメラ・各シャドウカスケード・水面ごとに選別）
2. シャドウアトラス: 4 カスケード（遠景は前フレームからキャッシュ）＋水面用マップ
3. G-buffer → SSAO
4. 体積雲（2×2 ブロックごとに 1 テクセルを毎フレーム計算し、残りは再投影）
5. ディファード・ライティング
6. 半透明の水と氷（フォワード、ライティング済みシーンの屈折＋SSR）
7. 大気効果（近距離フォグの影付きマーチは半解像度）、光芒
8. TAA（レンダースケール < 1 のときアップスケール）
9. ブルーム下降チェーン → 1/4 レベルから自動露出 → ブルーム上昇チェーン
10. 最終合成 → スワップチェーン

大気は事前計算 LUT（transmittance / multiscatter / skyview / sky ambient）。

## 依存関係

`wc_game.c` が全体を束ね、`wc.h`（ワールド・ブロック・生成・メッシュ）と `wc_game.h`（ゲーム状態・UI・音・入力）、
`wc_render.h`（描画）を共有ヘッダーとする。各システムの詳細は SYSTEMS_DOCUMENTATION.md。
